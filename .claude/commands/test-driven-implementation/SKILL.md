# Test-Driven Implementation

プログラム実装リクエストに対し、実装→テスト仕様書作成→テスト実行→バグ修正→全Pass確認→完了報告の6フェーズで進める。

## 適用範囲

- バックエンドAPI開発
- フロントエンド開発
- フルスタックアプリ開発
- Dockerコンテナ環境での開発

## 対象外

- 外部API連携の環境依存問題
- ファイアウォール設定
- 本番環境特有の設定問題
- 複雑なエッジケースや負荷テスト

## 6フェーズ実装プロセス

### Phase 1: 実装

要求された機能を実装する。

### Phase 2: テスト仕様書作成

必須項目:
- テスト項目ID (T001, T002...)
- テスト内容の説明
- 実行手順 (コマンドまたは操作手順)
- 期待される結果
- テスト結果欄 (Pass/Fail)
- 実行日時欄
- 備考欄

テストケース選定は [references/test-case-guide.md](references/test-case-guide.md) を参照。

### Phase 3: テスト実行

1. Docker環境を起動 (必要な場合)
2. 各テストの結果をPass/Failで記録
3. 実行ログを保存

### Phase 4: バグ修正

Fail項目がある場合:
1. コードを修正
2. 修正内容を明記
3. 該当テストを再実行

### Phase 5: 完全性確認

全テスト項目がPassになるまでPhase 3-4を繰り返す。修正履歴を記録する。

### Phase 6: 完了報告

全テストPass後のみ、以下のフォーマットで報告する:

```
実装完了

【成果物】
- 実装ファイル: (ファイル一覧)

【テスト結果サマリー】
- 総テスト項目数: X
- Pass: X
- Fail: 0
- 修正回数: X回

【最終確認】
- 全テスト項目実行済み
- 全テスト項目Pass
- 基本動作確認完了
- Dockerコンテナ内で動作確認済み (該当する場合)
```

## 禁止事項

- テスト実行前に「実装完了」と報告すること
- テスト項目にFailがある状態で完了すること
- テスト仕様書を作成せずに完了すること
- 基本的なエラーを残したまま完了すること

## 必須事項

- 全テスト項目を実際に実行すること
- Fail項目は必ず修正すること
- 全テストPass後のみ完了報告すること
- テスト結果と修正履歴を記録すること
- Dockerコンテナ内でのテストを優先すること
