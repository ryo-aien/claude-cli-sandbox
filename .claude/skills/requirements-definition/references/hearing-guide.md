# ヒアリングガイド

ヒアリングモードで使う質問バンク。上から順に全部聞くのではなく、会話から埋まらない部分だけを選んで聞く。1ターン1〜3問、可能な限り選択肢付きで。

## フェーズ1: 背景・目的（最初に必ず）

- 今、何に一番困っていますか？ / このプロジェクトが動き出したきっかけは？
- これが実現したとき、誰のどんな状態が変わっていれば成功ですか？
- 逆に、これをやらなかったら何が起きますか？

> 「作りたいもの」から入るユーザーが多いが、必ず一段上の目的に戻す。目的が固まると後続のスコープ判断が全て楽になる。

## フェーズ2: 現状と課題

- 今その業務はどうやって回していますか？（Excel / 紙 / 既存システム / 人力）
- その中で一番時間がかかっている・ミスが起きているのはどこですか？
- 月に何件くらい / 何人くらいが関わりますか？

> 定量情報（件数・人数・頻度）は必ず1つは取る。効果試算と非機能要件の根拠になる。

## フェーズ3: スコープ

- 今回のシステムで扱う業務の始まりと終わりはどこですか？（例: 注文受付から請求書発行まで）
- 逆に、今回は手を付けないと決めていることはありますか？
- 一度に全部作りますか、それとも段階的に？

## フェーズ4: 利用者

- 使うのは誰ですか？（部署・役割・人数）
- ITに不慣れな人も使いますか？
- 社外の人（顧客・取引先）も使いますか？

## フェーズ5: 機能要件

- 理想の一日の流れを教えてください。朝システムを開いてから、最初に何をしますか？

> この「一日の流れ」質問は機能の洗い出しに非常に有効。ユーザーは機能一覧を語れなくても、業務の流れは語れる。

- 通知やリマインドは必要ですか？
- 承認フロー（上長のチェックなど）はありますか？
- 帳票・CSV出力・印刷は必要ですか？
- 検索や集計で「これができたら最高」というものは？

## フェーズ6: 非機能・制約

選択肢で聞くと答えやすい:

- 止まったらどれくらい困りますか？（1時間で業務停止 / 半日なら耐えられる / 翌日復旧でOK）
- 扱うデータに個人情報や機密情報は含まれますか？
- スマホからも使いますか？
- 予算感・希望時期は決まっていますか？（ざっくりでOK / 未定ならTBD）
- 既存システムとの連携は必要ですか？

## フェーズ7: クロージング前の確認

- ここまでで「これも伝えておきたい」ということはありますか？
- 未確定として残した項目（TBD一覧を見せる）のうち、社内で確認できそうなものはどれですか？

## ヒアリングのコツ

- 選択肢は直前までの回答内容から作る。ユーザーが使った言葉（部署名、ツール名、業務名）をそのまま選択肢に入れると、答える負担が一気に下がる。
- ユーザーの発言をそのまま要件にせず、「つまり◯◯ということですか？」と要件の形に言い換えて確認する。
- 「全部欲しい」と言われたら、「最初のリリースに絶対必要なものはどれですか？」と優先度に変換する。
- 沈黙や「わからない」は失敗ではない。「では一般的な◯◯を仮置きします」と進め、TBDに記録する。
