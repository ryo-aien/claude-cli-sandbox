# 参考サイト一覧

デザイン作業に入る前に、ここに載っているサイトの中から作成物に合うものをAI自身が判断し、実際に読み込んで（WebFetchやブラウザツールで）参考にする。合致するものが複数あれば複数読み込んでよい。全部を毎回読み込む必要はない。使い方は `SKILL.md` の「参考サイトを自分で選んで読み込む」の章を参照。

新しい参考サイトが増えたら、このファイルにディスクリプションを追記していく。

---

## 1. デジタル庁デザインシステム（DADS）— Foundations

- **URL**: https://design.digital.go.jp/dads/foundations/
- **どんなサイトか**: 日本政府のデジタルサービス向けデザインシステムのうち、カラー・タイポグラフィ・アイコン・レイアウト・リンクテキスト・余白・角の形状・エレベーションといった「土台となる設計ルール」をまとめたセクション。JIS X 8341-3:2016 / WCAG 2.2 準拠。
- **こんな作成物に向く**: 行政・自治体・公共サービス、業務システム、金融・保険など「誤読・誤操作が許されない」サービス、アクセシビリティ基準を厳密に満たす必要があるサイト。
- **得られるもの**: 色や余白などの「基礎トークン」の考え方、堅実で読みやすい配色・文字組みの参考。

## 2. デジタル庁デザインシステム（DADS）— Components

- **URL**: https://design.digital.go.jp/dads/components/
- **どんなサイトか**: 同デザインシステムのコンポーネントカタログ。アコーディオン、タブ、パンくず、バナー、ダイアログ、テーブル、カード、ドロワーなど50以上のUI部品の実装パターンを掲載。
- **こんな作成物に向く**: フォームや通知、ナビゲーションなど「型が決まったUI部品」を大量に扱う管理画面・行政サービス・業務システム。コンポーネント単位の状態設計（hover/focus/disabled等）の参考が欲しいとき。
- **得られるもの**: 個々のコンポーネントのバリエーション・状態・アクセシビリティ実装の具体例。

## 3. 一休.com デザインガイドライン — Philosophy

- **URL**: https://www.ikyu.co.jp/design_guideline/philosophy
- **どんなサイトか**: 宿泊・レストラン予約サービス「一休」の「一休らしいデザイン」を定義するガイドライン。プロダクト全体で一貫した体験を提供するための思想・哲学を記したページ。
- **こんな作成物に向く**: 高級感・上質さ・信頼感を演出したいtoCサービス、予約・EC・宿泊/飲食など体験価値を売るサービス、ブランドの世界観を統一したいプロダクト。
- **得られるもの**: 機能要件だけでなく「ブランドらしさ」をデザイン判断にどう落とし込むかという思想面の参考。

## 4. freee デザインシステム「Vibes」

- **URL**: https://vibes.freee.co.jp/?path=/docs/doc-readme--docs
- **どんなサイトか**: 会計・人事労務SaaSを展開するfreeeのデザインシステム「Vibes」のStorybookドキュメント。コンポーネント・トークン・ガイドラインをコードと共に確認できる。
- **こんな作成物に向く**: SaaS・業務管理系のtoBプロダクト、複雑なフォームやデータ入力が多い画面、開発者にそのまま実装させたいデザインシステム構築。
- **得られるもの**: 実装（コード）と一体化したデザインシステムの構成例、SaaSらしい機能的で分かりやすいUIの参考。
